# US-001 — Predictable partial updates via cleaned-up playbook tags

**Status:** Approved
**Epic:** Tag Hygiene

## Description

As a developer maintaining this workstation repo,
I want the playbook's partial-update tags cleaned up and made consistent,
so that running any tag updates exactly the tools I intend — completely and safely — every time.

## Context & Scope

**In-scope:**
- Tag cleanup across `local.yml` and all 6 roles
- Exactly one predictable tag per role + fine-grained tags (`dotfiles`, `python`, `nvm`)
- Every documented tag runs *complete* — supporting setup never silently skipped
- The tag list discoverable via one command

**Out-of-scope (MVP trims):**
- Adding any new capability or tool
- Changing the `setup.sh` CLI (documented commands keep working as-is)
- New tasks beyond dep-inclusion fixes needed for tag safety
- Extra fine-grained tags beyond `dotfiles`/`python`/`nvm` — can be added later if the iteration need appears

## Acceptance Criteria

1. **Given** a fresh clone, **When** the user runs any documented tag, **Then** only tasks belonging to that concern run — no tasks from other concerns.
2. **Given** the user runs a fine-grained tag (e.g. `python` or `dotfiles`), **Then** all supporting setup for that tag runs too — no "tag completes but the tool can't work because its deps were excluded" case (the current `vagrant` gap).
3. **Given** the user runs a role tag, **Then** it updates everything that role provides.
4. **Given** the user consults the available tags, **Then** the list is discoverable with one command and matches reality.
5. **Edge case:** **Given** the user runs a typo'd or undocumented tag, **Then** it is a harmless no-op with nothing left half-configured.

## Technical Guidance

See `docs/decisions/ADR-001.md` and the constraints from the Architect gate
(role tags only in `local.yml`; fine-grained tags only on tasks; `always`
pre-tasks untouched; no changes to `become` flags, `when` conditions, or task
ordering).
