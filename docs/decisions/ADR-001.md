# ADR-001: Role-scope tags + minimal cross-cutting fine-grained tags

**Status:** Accepted

## Context & Problem Statement

The playbook exposed 23 tags across three layers (role-level in `local.yml`,
group tags inside roles, plus ad-hoc extras). Fine-grained selection was
incomplete in proven ways: `--tags dotfiles` templated `.bashrc_extras`
without wiring it into `.bashrc` (untagged task), and `--tags vagrant`
installed the vagrant-libvirt plugin without its build dependencies.
A decision was needed to make partial updates predictable.

## Decision Drivers

- Predictability of partial updates (complete by construction)
- Minimal conceptual surface for a personal playbook
- No new tooling or collections
- Fast iteration on frequently-touched dotfiles and language tooling

## Considered Options

1. **Status quo** — 23 tags, flexible but provenly unsafe. Rejected.
2. **One tag per role only** — safest and simplest, but no fast dotfile/language iteration. Rejected per Product Owner.
3. **Role tags + 3 fine-grained cross-cutting tags (`dotfiles`, `python`, `nvm`)** — chosen.

## Decision Outcome

Role tags (`core`, `system`, `terminal`, `languages`, `docker`,
`virtualization`) are declared only in `local.yml` and apply to every task in
their role automatically. Fine-grained tags are declared only on individual
tasks and may cross roles (`python` covers the languages role's pyenv tasks
and the system role's Python build-dependency task). Concern-scoped selection
beyond the 3 fine-grained tags runs the whole role.

**Positive consequences:** every tag combination safe and complete; tag count
23 → 9; tag list discoverable via `--list-tags`.

**Negative consequences:** less granular runs — fonts, starship, kvm,
hashicorp, and vagrant partial updates now execute the whole role (slower but
safe); `python` spans two roles, a pattern future contributors must know
(documented here and in `setup.sh --help`).

## Technical Implementation Guidance

- Role tags live only in `local.yml`; task files carry only fine-grained tags.
- The `pre_tasks` in `local.yml` keep `tags: [always]` untouched.
- Fine-grained tags must be complete: every dependency for that concern
  carries the tag.
- Do not alter `become` flags, `when` conditions, registered vars, or task
  ordering when adjusting tags.
